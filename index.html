01六句話

整份筆記的結論。第 2 到第 7 節逐一展開。

  1. 背景圖的驗收標準是「還能放字嗎」。畫面漂亮但塞滿資訊，就當不成背景。
  2. 題材本身要撐得起場面。飛機比滑翔翼合適，火箭比熱氣球合適，貨輪比翻覆的船合適。這一步選錯，後面的提示詞救不回來。
  3. 留白是深藍到黑的暗場。最關鍵也最容易漏掉的一條，多數人會直覺去做亮天空。改成暗場之後，白字對比從個位數跳到二十上下。
  4. 震撼感來自對比，代價是留白。把很小的東西放進很大的環境才有力量；但尺度失衡會把可放字的區域從四塊壓到三塊。
  5. 加一個發光點就有視覺中心，而且不用付代價。可放字區一塊都沒少，對比度還變高。三招裡成本最低、最該先用的。
  6. 動態背景的門檻比想像中低。用 ffmpeg 從一張靜圖就能做出接得回去的循環運鏡，不必等 AI 生影片。

02判準：什麼樣的圖能當背景

一句話好看不是標準，放得下字才是。

常見的失敗流程是這樣：打開生圖工具，輸入「一艘揚起白帆的帆船，在平靜藍色的海面上行駛」，得到一張很好看的圖，然後發現它沒辦法用。

失敗有三種長相：

  • 畫面太複雜：資訊塞滿，字放上去會被吃掉。
  • 畫面太平：沒有層次也沒有主角，整張圖像一塊布。
  • 沒有留白：最致命的一種，前兩種還能靠修圖救。

反過來說，可用的背景圖要同時滿足四件事：足夠的留白區塊、單一而清楚的視覺主體、可控的明暗對比、跟主題對得上的敘事張力。

影片裡的原話是「背景圖好看的標準就是具有恢弘感」。我把它拆成上面四項，因為「恢弘感」不能拿來驗收，留白率跟對比度可以。

所以我們做了一把尺

這份筆記的每一個數字都出自 experiments/verify.py。它把畫面切成六塊候選文字區，每塊量兩件事：

  • 平坦度：亮度標準差要小於 0.12。花紋太多，字會被吃掉。
  • 對比度：白字或黑字至少一種的 WCAG 對比度要大於 5.0。

兩項都過的算一塊可用，寫成「幾 / 6」。門檻訂 5.0 是因為任何平坦色塊都過得了 WCAG 的 4.5，那條線擋不住東西。工具本身也有負控制：verify.py --self-check 會確認純黑圖六塊全過、隨機雜訊圖一塊都不過、中間調死區不過。

03配方：提示詞的六段結構

一句話留白要寫成「深藍至黑色留白」，主體要寫成「亮度明顯高於環境」。漏掉這兩句就會生出普通的風景照。

第 4 集的影片畫面上直接把完整提示詞打出來了，逐字讀回來是這樣（原文為簡體，照原樣引用）：

提示词：一个宇航员坠落在银河中心。倾斜构图。银河由恒星、柔和星云与细腻星尘构成。银河整体呈现流动、半透明的光带形态，如同被引力弯曲的银河旋臂，空间干净而开阔，背景为深蓝至黑色留白。宇航员及其周围被暖金色主光源照亮，宇航员轮廓清晰、对比强烈，亮度明显高于环境，强调尺度对比与孤独感。 极简风格，超现实宇宙场景，超广角视角，电影级光照，轻体积光获奖摄影作品。

提示词：前景：一名宇航员在画面的左下角，背对镜头坐在崎岖岩石上，穿着写实宇航服，仰望天空上的地球，荒凉的岩石地貌延伸至地平线。远景：薄雾般的云海与低矮山峰，天空中一颗巨大地球占据画面上方，地球边缘带有冷色轮廓光，深空背景布满恒星、星云与微弱星尘。整体色调偏冷的深蓝、灰蓝与暗褐色。高对比，电影级光影，史诗感与孤独感并存，超写实，科幻概念艺术，8K，高细节，宽画幅构图

拆出來的六段

  1. 前景與遠景分開寫。前景交代主體在畫面哪個角、姿態、朝向；遠景交代環境層次。
  2. 主體極小、環境極大。明寫「強調尺度對比與孤獨感」。
  3. 留白是暗場。「空間乾淨而開闊，背景為深藍至黑色留白」。
  4. 主體要比環境亮。「被暖金色主光源照亮，輪廓清晰、對比強烈，亮度明顯高於環境」。標題那兩個字「點亮」就是這個意思。
  5. 冷色調加高對比。深藍、灰藍、暗褐。
  6. 風格詞收尾。極簡風格、超現實、超廣角視角、電影級光照、輕體積光、科幻概念藝術、8K、高細節、寬畫幅構圖。

04三招，以及它們各自的代價

一句話選題材是免費的，加光是免費的，尺度失衡要拿留白去換。

第一招：選對題材

要有場面。飛機比滑翔翼合適，火箭比熱氣球合適，貨輪比翻覆的船合適。這一步選錯，後面的提示詞救不回來。

第二招：尺度失衡

把主體放進一個不屬於它的宏大情境裡。定義很精準：尺度失衡指的是失衡，不是宏大。旋轉的風暴已經夠宏大了，畫面卻很無聊；在風暴中心放一艘小小的帆船，故事感立刻出現。

三種做法：

  1. 把視野一路拉遠。帆船在湖面上，改成拉遠到看得見地球輪廓，再拉遠到漂浮在宇宙中心。
  2. 把小主體丟進大環境。風暴中心的帆船、一本書上加班的太空人。
  3. 用擴圖反覆擴邊界。沙漠中奔跑的馬，擴出沙漠的邊界，史詩感就出來了。

換主體不換方法：失重的太空人、躍入銀河的鯨魚、象徵榮譽的獎盃、壓迫到地面的巨型星球，共通點是主體被放進遠大於它的容器裡。

代價：可放字的區域會變少

這是自己跑對照實驗才發現的，來源影片沒有講。

風暴眼裡的小帆船是所有圖裡最有力量的一張，但風暴雲填滿了整個畫面，唯一夠平坦的只剩右下那塊暗角。要用這招就要接受標題只有一個位置可以放。

第三招：光

在任何平淡畫面上加一個發光元素，就有了視覺中心。成本最低，而且可以直接加在既有的圖上。

  • 海浪：白天換成黑夜，再在浪花上打一束光。
  • 山脈：深藍色的山沒有張力，加上「讓山上遍布流金色的脈絡」就有記憶點。
  • 通用：發光的面罩、綿延的車流、發光的電腦，都能給觀眾一個強烈的視覺中心。

配色可以隨便換，前提是結構不動

同一組提示詞只換發光顏色，跑了三種：

顏色隨便換都好看，是因為暗場與發光主體的關係沒有動。這句話的完整版應該是「結構對了以後，配色可以隨便換」。

05讓背景動起來

一句話不必等 AI 生影片。ffmpeg 從一張靜圖就能做出接得回去的循環，而且比 AI 可靠。

原片教的做法

圖生影片。分兩種情況。圖片本身就有動態，順著運動邏輯描述即可，短到一句就夠：

海浪拍打船頭。 鯨魚在海面翻騰。 讓天空中的雲層飄動起來，有一種時間流逝的感覺。

圖片偏靜態，用這句萬用公式：

以 XX 為中心，旋轉運鏡。

需要固定主體位置就補一句「保持貨輪在畫面中的位置不變」。本身已經有動態的畫面再疊一層旋轉運鏡，張力會再翻一倍。元素動態加運鏡的配方是固定結構：先描述關鍵元素的動態，再指定運鏡方式。

星雲順時針旋轉 + 環繞運鏡 徒步者向上攀登的背影 + 跟隨運鏡 駿馬原地奔跑、絲帶飄動 + 固定鏡頭

要無限循環就把首幀和尾幀設成同一張圖，再描述兩幀之間的過渡。

我們實際能跑的做法：ffmpeg 無縫循環

關鍵是把 zoompan 的所有運鏡參數寫成 1-cos(2*PI*on/N) 的形式。這個式子在第一幀與最後一幀的值相同，所以首尾幀由結構保證一致，循環播放不會跳。

z = 1 + 0.10 * (1 - cos(2*PI*on/N)) / 2 推近，一進一出回到原點 x = iw/2 - iw/zoom/2 + iw*0.055 * (1 - cos(2*PI*on/N)) / 2 橫移，飄出去再飄回來

驗法是抽出第一幀與最後一幀逐像素比對平均色差：

成品長度檔案大小首尾幀平均色差
銀河，緩慢推近12 秒1000 KB2.54 / 255
沙丘，推近加橫移12 秒502 KB0.46 / 255

剩下那 2.54 是 H.264 在銀河那種密集紋理上的壓縮雜訊，不是畫面跳動。這條路比 AI 的首尾幀同圖更可靠，因為無縫是算出來的。代價是它只能做推近與平移，做不出真正的環繞：平面的一張圖沒有深度資訊，繞不過去。這正是「以 XX 為中心，旋轉運鏡」非得靠圖生影片的原因。

成品在對照實驗投影片的第 15、16 頁，可以直接翻到那裡放。

放進簡報要注意的

  • 用 mp4，不用 gif。
  • 標籤寫 <video autoplay muted loop playsinline>。
  • muted 是自動播放的必要條件，瀏覽器擋的是有聲音的自動播放。背景影片本來就不需要聲音。
  • playsinline 是給 iOS 的，少了它 iPhone 會跳全螢幕播放器。

實測讀回來的狀態：

paused: false muted: true loop: true readyState: 4 duration: 12 解析度 1600x900 播放時間 2.97 秒 → 4.77 秒（確實在前進）

圖生影片這條路目前走不通

我們手上能用的是自架在區網那台的 gemini-web（Veo）。四次實跑全部逾時：728、1448、189、1448 秒，而且原因不是它慢。

  • 影片能力只有一個帳號有。/api/capabilities 回 video_capable: [2]，四個帳號裡只有第二個做得到。
  • 那支 API 只吃文字，不吃圖。VideoRequest 只有 prompt 與 timeout，所以現成的路是文生影片。底層的 _generate_media() 其實已經有 ref_path 可以掛檔，接上去就有圖生影片，還沒做。
  • 連文生影片都失敗。log 說進得了影片頁也找得到輸入框，但等滿之後頁面上一個 video 節點都沒有；截圖每次都停在「建立影片」的範本牆，對話串裡沒有任何使用者訊息。換 37 個字元的最短提示詞也一樣，排除提示詞太長。
  • 修掉兩個真的 bug 之後仍然失敗。那台機器上有一份寫好卻從沒生效的修正（服務比它早十分鐘重啟），修的是「檢查讀到 Quill 隱藏緩衝區」與「送出鈕的 aria-label 配不上」。已經 commit、開 PR、重啟讓它生效，影片第四次還是同樣的失敗。所以那兩個 bug 修得對，卻不是這條路壞掉的原因。

目前指向那個頁面本身：「建立影片」的落地頁寫著「試用範本或在對話中描述想生成的影片」，而服務是在範本牆的輸入框打字。合理的推測是那個輸入框不是真正的送出入口。這一步要開真瀏覽器互動看一次才能確定，還沒做。

06手上已經有圖，或完全沒有圖

一句話修圖是把不能用的救成勉強能用，不是把它變成好圖。

手上有一張醜圖：三步

公司的簡報常常沒得選圖。三個動作，順序不固定，看圖決定先做哪一個：去干擾、擴留白、壓暗背景突出主體。另一個常用的第零步是換天氣。

來源影片用的是豆包的內建擦除與擴圖。我們改用 Codex CLI 的 image-edit 模式跑同一套，看換掉工具還成不成立：

原圖2 / 67.240.1101
換天氣3 / 68.570.0986
去干擾3 / 68.400.0970
壓暗並留白4 / 68.720.0858
  • 整條流程有效，但幅度有限。2/6 修到 4/6、對比 7.24 拉到 8.72。跟一開始就寫對配方那批（6/6、對比 20 上下）差一個量級。手上真的有圖非用不可才走這條。
  • 換天氣那步效果最明顯（7.24 到 8.57），壓暗突出主體次之。這兩步換工具照樣複製得出來。
  • 去干擾與擴圖換了工具就不等價。去干擾沒做乾淨，右側那根電線桿三步都還在。擴留白那步更明顯：豆包的擴圖是把邊界往外推，這裡的模型是整張重畫，天空變多是重新構圖的副作用。要真的擴圖得找有 outpainting 的工具，不能靠提示詞叫模型「延伸畫面」。

整份簡報都沒有圖

全是文字的簡報排不出版面。做法是給 AI 一張參考圖，加上簡報裡的幾個關鍵詞，讓它生成一整套風格統一的圖示。重點在風格統一：同一張參考圖是整套圖示的錨，換了參考圖就要整套重生成。

07另一條路：用程式畫背景

一句話程式畫的留白是算出來的純色，平坦度贏過所有 AI 生的圖。

寫了一支，在這裡（會動）。純 WebGL 的 fragment shader，沒有引用任何函式庫，照同一套配方畫：暗場留白佔多數、單一暖色發光核心當視覺中心、核心刻意放右下把左上留給標題。

代價是它畫不出具象主體，只能做抽象的光與結構。而且它本身就在連續旋轉，檔案大小是零，任意解析度。要的是「會轉的抽象背景」時，這條路最划算。

還有哪些前端技術可以當背景

用 HTML 生成簡報的話，背景可以是一段會跑的程式：

要什麼效果用什麼怎麼要
三維動畫背景Three.js直接描述，例如「流動彌散漸變，四個顏色，前景一個金屬立方體，隨滑鼠位置旋轉」
現成三維場景Spline 社群找到喜歡的效果，remix 後匯出 embed 連結貼給 AI
著色器特效Shadertoy複製現成程式碼，連同修改要求一起送出
二維 WebGL 特效Unicorn Studioremix 後匯出 HTML 嵌入碼
物理動畫Matter.js描述要哪種物理行為，並要求觀眾可以操作
互動插畫Rive 社群下載動畫資源檔上傳，要求嵌入並自動播放
圖表ECharts貼官方範例程式碼，或直接上傳 Excel 與 CSV
地圖Mapbox指定暗色、亮色或寫實風格，要求可拖曳縮放

我們只實作了 fragment shader 這一條。其餘七條來自文件，沒有動手做過。

這條路的已知缺陷：所有用 HTML 生成簡報的產品，都沒有好辦法做跨頁調整。想把第 2 頁的內容挪到第 5 頁，或把第 3、4 頁合併，都會變成大規模返工。解法是回到原始做法：先用文字把每一頁的內容邏輯梳理清楚，再一次送進去生成。

08動手前的檢查清單

選題材

  • 這個主體撐得起場面嗎（飛機、火箭、貨輪、鯨魚、星雲、山）
  • 它跟簡報主題對得上嗎，還是只是好看

寫提示詞

  • 前景與遠景分開寫了嗎
  • 有寫「背景為深藍至黑色留白」嗎
  • 有寫「主體亮度明顯高於環境」嗎
  • 風格詞收尾了嗎（極簡、超現實、超廣角、電影級光照、8K、寬畫幅）

驗收出圖

  • 標題放得下嗎，留白區塊在畫面的哪一側
  • 白字或黑字，至少有一種讀得清楚嗎
  • 畫面有沒有單一而明確的視覺中心
  • 如果覺得無聊，缺的是尺度對比還是發光元素

轉動態

  • 推近與平移用 ffmpeg，運鏡參數寫成 1-cos 保證接得回去
  • 要真正的環繞運鏡，只能靠圖生影片
  • 存成 mp4，插入後加 autoplay muted loop playsinline

09這份東西怎麼驗的

一句話十九張自己生的圖加一支自己寫的 shader，全部走同一把尺量過；沒驗過的也列出來。

方法

  • 圖走本機 Codex CLI 的 $imagegen（吃 ChatGPT 訂閱額度）。進 repo 前一律轉成 JPEG。
  • 量測用 experiments/verify.py，判準與負控制寫在第 2 節。
  • 對照實驗每組只動一個變數。
  • 對照實驗投影片裡標題放在哪一塊、用什麼字色，是程式照量測結果決定的，不是手動調的。

驗過的

宣稱怎麼驗的結果
提示詞四段結構有用同主體 A/B 各一張1/6 到 3/6，成立
尺度失衡讓畫面更有張力同上張力成立，但可放字區 4/6 掉到 3/6，有代價

還沒驗的

  • 換生圖工具的反應。全部十九張圖都走同一個模型。來源示範用的是豆包，換成它、Midjourney 或 Seedream，同一組提示詞的反應會不一樣。
  • 四段結構與尺度失衡沒有重複樣本。只有隨機性那一組驗過重跑三次，這兩個結論各只有一張對一張。
  • 圖生影片沒有成品。「以 XX 為中心，旋轉運鏡」這句萬用公式一次都沒真的跑成功過。
  • 第 7 節其餘七條路只驗了一條。Spline、Rive、Matter.js、Mapbox、ECharts 都沒實作。
