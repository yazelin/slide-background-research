06選之前先看三件事

  1. 你要交出去的是什麼檔。要 PPTX 讓對方自己改，就往丙類或丁類找，或用有 PPTX 匯出的 skill。要上台講、要能內嵌真站，網頁簡報才成立。
  2. 授權。這批裡有幾個是 AGPL-3.0（guizang、dashi、banana-slides）。自己做自己用沒事，但產物如果內嵌了它的 runtime 又放上公開網站或拿去商用，條款要自己看一眼。標「自訂」跟「未標」的更要小心，沒有 LICENSE 檔等於保留所有權利。
  3. 還有沒有在動。甲類幾乎都是 2026 年 4 月後開的，其中好幾個已經三四個月沒更新。挑之前先看最後更新日期。

07我們為什麼自製

一句話這一批 skill 都在解排版，我們卡的是講者現場。

這台機器上裝著兩套，用途不重疊：自己寫的 slide-deck-skill，跟裝來對照的 dashi-ppt-skill。

順序要先講清楚：正確的做法是先跟 AI 討論出需求，再從需求開出功能規格，最後才做。下面這張表是倒著給你看的，因為功能早就做完了，它的用途是當證據，讓你檢查每一條功能背後都真的有一次需求。照著這張表從右往左推，方向是錯的。

要 demo 真站台，截圖是死的單頁內嵌 iframe，按了才載，不是一翻到就連線
直播網路會出事，demo 掛掉就冷場每個 demo 配一支預錄影片，按一下就切過去

查證一：dashi 有沒有講者主控台

沒有。它畫面上那個「演示控制台」是編輯與匯出工具列，跟講者無關：播放預覽、匯出 HTML 離線包與 PDF 與 PPTX、重置、切語言、切明暗、左側縮圖目錄、預覽風格切換、十種換頁動畫、右側的可調控件面板。

  • speakernote、presenternote、演讲者备注、讲稿：在模板、SKILL.md、README、版式清單裡零命中。搜到的「備註」全部是表格版式的欄位名。
  • window.open、BroadcastChannel、requestPresent：在模板與 scripts/ 裡零命中，所以沒有第二視窗或雙螢幕同步機制。
  • 計時器：搜 pace 有命中，但逐一看過是字型名 Space Grotesk 的子字串，沒有計時功能。

查證二：AGPL 的產物到底有沒有內嵌 runtime

HTML 產物會，PDF 與 PPTX 不會。

  • src/renderDeck.jsx 第 152 行每次算繪都會產生 assets/imported-theme-runtime.js，scripts/validate-swiss-deck.mjs 第 32 行還會檢查這個檔存在。所以任何一份 HTML 產物一定帶著它。
  • 它是單主題自包含的 IIFE。dist/theme-runtime/ 十二支合計 19 MB，單支介於 0.70 MB 到 0.77 MB 之間，一份 deck 只會帶用到的那一支。
  • PDF 走 Playwright 截圖，PPTX 走 html-deck-to-pptx 管線，兩者都是算繪結果，裡面沒有 JS。

可以照著做的結論：拿 dashi 做完，交 PDF 或 PPTX 給對方，不會碰到 AGPL 的散布條款。把匯出的 HTML 離線包放上公開網站或商用，就等於連同它的 runtime 一起散布，條款要自己看一眼（AGPL 的重點在第 13 條：透過網路提供服務也算散布，要提供對應原始碼）。

這一段只是把原始碼翻出來看到什麼就寫什麼，沒有法律效力。真的要商用，條款請自己讀或問律師。

結論

兩個都留著。要交報告、要 PPTX 檔、對方要自己改字，dashi 贏；要上台講、要備註計時遙控、要當場內嵌真站台，自製這套贏。規格是自己的資產，乙方可以換。
